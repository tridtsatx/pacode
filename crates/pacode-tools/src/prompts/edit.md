Edit a file by line anchors. `read` shows each line as `LINE#HASH| text`; pass those anchors (`12#ab`) in `ops` instead of retyping unchanged text. Ops: `replace` {start, end?, lines} (inclusive range), `insert_after` / `insert_before` {at, lines} (`at` may be `BOF` or `EOF`), `delete` {start, end?}. `lines` is the new text, one array item per line, without anchors. All anchors refer to the file as you last read it; ops must not overlap; list them in any order. If an anchor is stale the whole edit is rejected and the current anchored lines are returned: retry with those. Small line drift is corrected automatically. Fallback form (avoid): `old_string`/`new_string`/`replace_all` exact replacement. Other agents may be editing the same files concurrently. You must `read` an existing file before changing it. A change that would overwrite lines someone else modified after your read is rejected; the rejection names who changed which lines and shows them with fresh anchors, which count as read, so retry directly (or re-read only the indicated line ranges, never the whole file). Changes elsewhere in the file are reported but do not block you.
